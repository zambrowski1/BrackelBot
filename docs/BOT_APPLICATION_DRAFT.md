## Назначение и источники

Обслуживание существующих статей футболистов клубов Первой немецкой Бундеслиги.
Сезонные клубы определяются через API-Football league=78. Источник статистики:
API-Sports v3; структура и идентичность — MediaWiki API и Wikidata. Дополнительные
сведения о сборных и сложных переходах — отдельный подтверждённый ручной JSON.
Статьи и биографические разделы автоматически не создаются.

## Алгоритм предлагаемой первой задачи

Оператор подтверждает API ID, QID, статью и карьерную базу. Бот получает полный
сбор сезона, проверяет состав клуба и трансферы, вычисляет карьерный итог как
подтверждённую базу плюс дельту сезона. В существующей таблице меняется только
колонка чемпионата; итоги пересчитываются при известных полных данных.
Неизвестные, уменьшившиеся или противоречивые показатели идут оператору.

Первая предлагаемая автономная категория — обновление подтверждённой числовой
статистики и связанных однозначных итогов на конкретном списке статей. Список
статей, сезон и виды операций будут записаны в явное разрешение по решению
сообщества. Изменение клуба, периода, сборной или структуры первоначально ручное.
Дата получения API фиксируется в отчёте; без подтверждённого охвата не используется
для автоматического изменения даты статистики в карточке.

## Частота и защита

Один цикл в сутки через Toolforge Jobs Framework. Вся обработка — Python без GUI.
Постоянное состояние — ToolsDB. Два цикла не работают одновременно. Данные
проверяются повторно перед записью; baserevid, basetimestamp и starttimestamp
защищают от конфликтов. Изменяется точный участок, ссылки, комментарии и сноски
сохраняются. Связанные операции публикуются одной записью. Повтор не создаёт правку.

Неопределённый результат сетевого запроса не приводит к повторному POST.
Аварийная блокировка в базе проверяется перед каждой записью. Журналы и копии
исходных ревизий сохраняются без паролей и API-ключей. Основное пространство
запрещено до явного включения конкретной одобренной задачи оператором.

## Испытания и примеры

Результаты локальных автоматических запусков приложены в verification-server.txt.
Регрессия ручных операций — tests/test_stage2.py и test_stage3.py; API и сервер —
test_api_football.py и test_server.py. Эти испытания используют имитации API.
Демонстрационные diff карточки и таблицы формируются автоматически тестами.
`examples/stage23/07-combined-atomic.json` содержит полный вымышленный сценарий
для testbot, включая переход, сборную, сезон и итоги.

По информации оператора прежняя версия прошла ручные тесты 4 (1) → 5 (2) и
old_value_mismatch. Разработчик новой серверной версии самостоятельно не
публиковал правок. Перед заявкой оператор должен приложить ссылки на реальные
тестовые ревизии, результаты авторизации/восстановления и журнал запуска Toolforge.
Пустые места нельзя объявлять успешно проверенными.

ПО: Python >=3.12, requests, mwparserfromhell, jsonschema, PyMySQL; локальный GUI —
PySide6. Код — MIT, копии Википедии сохраняют исходную лицензию и атрибуцию.

Оператор проверяет действующие [правила о ботах](https://ru.wikipedia.org/wiki/Википедия:Боты)
и [порядок заявки](https://ru.wikipedia.org/wiki/Википедия:Заявки_на_статус_бота)
перед подачей. Этот файл — технический черновик, не решение сообщества и не заявка.
