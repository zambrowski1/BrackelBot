# Данные, открытый код и воспроизводимость

Toolforge требует открытый код под OSI-approved лицензией; MIT этому требованию
соответствует. [Right to fork](https://wikitech.wikimedia.org/wiki/Help:Toolforge/Right_to_fork_policy)
также описывает открытые данные, отделение секретов и возможность получить
необходимые для копии инструмента базы. Публичный GitHub не означает
автоматического одобрения размещения или ботозадачи.

## API-Football

[Условия API-Football](https://www.api-football.com/terms), проверены 2026-10-08:
сервис не предоставляет лицензию на публикацию всех полученных данных;
права третьих лиц и необходимые разрешения проверяет пользователь. Аккаунт
и ключ нельзя передавать другим разработчикам. Поэтому открытый исходный код
не доказывает совместимость будущих API-дампов с Open Data Toolforge.

Перед эксплуатацией на Toolforge оператор должен выяснить применимые права
на статистику и её публикацию в Википедии, а также допустимость хранения и
открытого распространения необходимых данных. Неясности согласовываются
с правообладателями/поставщиком и администраторами WMCS. Пока вопрос не решён,
не публикуйте API-кэш или дампы и не заявляйте полную совместимость по данным.
Собственная лицензия проекта не распространяется на логотипы, фото или тексты API.

В репозитории нет реальных выгрузок API, ключей, ToolsDB, рабочих очередей или
паролей. Тесты API используют самостоятельно составленные синтетические ответы.
Новый оператор использует собственную подписку и формирует локальное состояние.

## Получение состояния для копии инструмента

Копию можно запустить с пустой базой (`init-db`), затем заново подтвердить
соответствия игроков/клубов и карьерные базы по SERVER_OPERATOR.md.
Toolforge-аккаунт, Wiki-аккаунт и одобрение ботозадачи не передаются при fork.
Для миграции своего инструмента оператор может экспортировать разрешённые данные:

```bash
./brackelbot/toolforge/operator.sh export players ../reports/players.json
./brackelbot/toolforge/operator.sh export clubs ../reports/clubs.json
./brackelbot/toolforge/operator.sh export anchors ../reports/anchors.json
```

Экспорт не является публичным dump и не обходит проверку прав. Обмена данными
с третьими лицами пока нет. Когда сервер будет создан, оператор указывает в
README контакт и порядок запроса разрешённых выгрузок, включая лицензии,
атрибуцию, исключение секретов и ограничения персональных данных.

Материалы Википедии в тестах имеют отдельную атрибуцию: [NOTICE.md](../NOTICE.md).
