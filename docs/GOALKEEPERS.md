# Пропущенные голы вратарей

В карточке вратаря `54 (-57)` означает 54 матча и 57 пропущенных голов.
В КлСтат пропущенные голы записываются как отрицательные целые числа;
итоги клуба и карьеры суммируются с сохранением знака.
Количество матчей всегда неотрицательно.

Бот определяет вратаря по `позиция` или `амплуа` в карточке `Футболист`,
содержащему «вратарь» или «goalkeeper». В старой карточке без позиции допускается
явное определение в первом абзаце: имя этого игрока, «футболист, вратарь»
со ссылкой `[[Вратарь (футбол)]]`. Упоминания других вратарей дальше по тексту
и минусы в статистике не определяют амплуа. Противоречащая позиция Sofascore
останавливает сбор. Для вратаря новые голы должны быть
неположительными, для полевых игроков — неотрицательными. Ноль допустим.
При отсутствии подтверждённого амплуа отрицательная новая статистика отклоняется.
Существующие положительные голы у вратаря можно исправить ручным пакетом,
если исходные числа и источник проверены оператором.

Ручная форма позволяет вводить отрицательные голы. JSON версий 1.0 и 1.1
поддерживает отрицательные `goals` в `expected`, `new` и структурных данных.
Исправления показываются в diff; сноски и комментарии сохраняются.

API-Football: для `games.position=Goalkeeper` используются `goals.conceded`,
а не `goals.total`. Значение источника 57 преобразуется в -57.
Если пропущенные голы неизвестны, они не заменяются нулём.
Карьерная база и сезонная статистика должны использовать один показатель.
Для нулевой базы вратаря задайте `goal_metric: conceded` явно;
для отрицательной базы показатель определяется по знаку.
Увеличение пропущенных голов (-54 → -57) считается ростом статистики;
уменьшение их количества (-54 → -50) требует проверки.

Sofascore использует поле `statistics.goals_conceded`, если оно есть в ответе.
Если поставщик его не возвращает, статистика вратаря остаётся на проверке.
Текущий адаптер Highlightly не извлекает пропущенные голы: обновление
вратаря из него блокируется проверкой показателя, включая нулевые значения.

Таблица отдельных матчей `СбМатчи` хранит забитые игроком голы в матче.
Её `голыN` остаются неотрицательными: это отдельный показатель,
пропущенные голы туда автоматически не переносятся.
