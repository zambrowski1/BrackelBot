# Highlightly

Источник выбирается переменной `BRACKELBOT_API_PROVIDER=highlightly` или
параметром `--provider highlightly` **перед названием команды**. API-Football
остаётся доступен через `--provider api_football`; по умолчанию используется он.

Используется прямой Football API: `https://soccer.highlightly.net`.
Ключ передаётся в заголовке `x-rapidapi-key`, без RapidAPI-посредника.
Основание: [документация авторизации](https://highlightly.net/football-api/documentation/getting-started/authentication/).

## Один ключ

На Toolforge, под `tools.brackelbot`:

```bash
toolforge envvars create BRACKELBOT_API_PROVIDER
# Значение: highlightly
toolforge envvars create HIGHLIGHTLY_API_KEY
# Ввести ключ по запросу команды.
```

На локальном компьютере задайте эти же переменные окружения. Ключи не записываются
в исходники, SQLite, ToolsDB, отчёты или Git. Команды ниже вызываются через
`toolforge/operator.sh` на Toolforge или `python -m wiki_stats.server_cli` локально.

## Несколько ключей

Вместо `HIGHLIGHTLY_API_KEY` задайте `HIGHLIGHTLY_KEYS`: JSON-массив.
Он имеет приоритет над одиночным ключом. Для пяти ключей **одного аккаунта**:

```json
[
  {"key": "REPLACE_KEY_1", "group": "default", "daily_budget": 100},
  {"key": "REPLACE_KEY_2", "group": "default", "daily_budget": 100},
  {"key": "REPLACE_KEY_3", "group": "default", "daily_budget": 100},
  {"key": "REPLACE_KEY_4", "group": "default", "daily_budget": 100},
  {"key": "REPLACE_KEY_5", "group": "default", "daily_budget": 100}
]
```

На сервере: `toolforge envvars create HIGHLIGHTLY_KEYS`, затем вставить JSON
**одной строкой**. Это пример формата, а не рабочие ключи. Список строк тоже
разрешён: все такие ключи попадают в общую группу `default`.

`group` обозначает общую квоту подписки. Пять ключей одной подписки не дают
пятикратный лимит. Для независимо предоставленных и разрешённых поставщиком
подписок указываются разные группы, например `subscription-a`, `subscription-b`.
Не создавайте группы для обхода лимита: это запрещено [условиями Highlightly, §7](https://highlightly.net/terms/).
Назначение уже использованного ключа в другую группу блокируется, чтобы смена
настройки не обнуляла расход.

`daily_budget` — дополнительный местный потолок на группу (по умолчанию 100).
Бот берёт меньший из этого бюджета и фактического остатка в заголовках ответа.
Для оплаченной квоты бюджет можно явно увеличить. Одинаковая группа требует
одинакового бюджета у всех её ключей.

Бот использует первый доступный ключ до исчерпания квоты. Затем переходит к
следующей независимой группе. Отклонённый ключ выключается; другой ключ той же
группы может заменить его, сохраняя общий расход. Ограничение частоты останавливает
весь пул на `Retry-After` (как минимум 60 секунд). Сетевые ошибки и HTTP 5xx не
вызывают ротацию или автоматические повторы. Отправленный запрос учитывается даже
при сетевой ошибке. Кэш не расходует квоту.

Расход и сбой ключа сохраняются после перезапуска. Для прямого Highlightly
дневная квота сбрасывается в полночь UTC — [условия, §4.2](https://highlightly.net/terms/).
Если ответы ещё не получены, `remaining` равен `null`: доступный местный бюджет
показывается как верхняя оценка, а не подтверждённый остаток на сервере.
Команда `api-quotas` не обращается к API. Ключи и названия групп в выводе заменены
необратимыми идентификаторами; `slot` — номер ключа в вашем JSON-списке.
Остатки ключей одной группы нельзя складывать. Все сетевые команды CLI держат общую блокировку
инструмента, включая операторские проверки; параллельные запуски отклоняются.

На Toolforge запускайте команды ниже **в контейнере Python**, а не напрямую на
SSH-бастионе. Например, проверка квот:

```bash
toolforge jobs run bb-quotas --image python3.13 \
  --command './brackelbot/toolforge/operator.sh api-quotas' --wait
tail -n 100 ~/bb-quotas.out
```

Остальные команды также передаются в `--command` целиком. На локальном
компьютере `python -m wiki_stats.server_cli` запускается обычным способом.

```bash
./brackelbot/toolforge/operator.sh check-api
./brackelbot/toolforge/operator.sh api-quotas
```

## Проверить данные и подтвердить игрока

```bash
./brackelbot/toolforge/operator.sh search-player 'Harry Kane'
./brackelbot/toolforge/operator.sh inspect-player 29778 --season 2026
./brackelbot/toolforge/operator.sh check-league --tier 1 --season 2026
```

`check-league --tier 2` и `--tier 3` проверяют другие немецкие дивизионы.
Ежедневный редактор пока работает с **первой** Бундеслигой. У Highlightly её ID
67162, второй — 68013, третьей — 68864. Число 78 в общих правилах бота обозначает
существующий логический охват ботозадачи; в запросы Highlightly оно не передаётся.

Названия в поиске — кандидаты, не доказательство личности. `player-confirm`
проверяет дату рождения, Wikidata и русскую статью:

```bash
./brackelbot/toolforge/operator.sh player-confirm PLAYER_ID \
  --qid PLAYER_QID --title 'Название статьи' --wiki-name 'Имя в карточке' --confirm
./brackelbot/toolforge/operator.sh club-confirm CLUB_ID \
  --qid CLUB_QID --title 'Название статьи клуба' --confirm
./brackelbot/toolforge/operator.sh anchor-confirm PLAYER_ID anchor.json --confirm
```

Формат `anchor.json` и порядок ручного подтверждения описаны в
[руководстве оператора](SERVER_OPERATOR.md). База должна содержать сезонные числа
**из выбранного источника** на дату подтверждения. Старую базу API-Football нельзя
автоматически переносить в Highlightly: поставщики могут считать статистику по-разному.
Все ID, связи, базы, планы, кэш, очереди проверки и история запусков провайдеров
хранятся раздельно. Аварийная блокировка и одобрение ботозадачи общие.

## Ежедневный запуск

```bash
toolforge jobs run bb-highlightly --image python3.13 \
  --command './brackelbot/toolforge/operator.sh run --dry-run --season 2026 --report-dir ../reports' --wait
```

Читаются только явно подтверждённые активные игроки. Профиль определяет текущий
клуб, дата рождения подтверждает личность, `perCompetition` определяет матчи и
голы за конкретный клуб, сезон `26/27` и турнир `Bundesliga` с типом
`national league`. Кубки и другие сезоны исключаются; карьерные итоги по всем
турнирам из `perClub` не используются. Неизвестные числа не заменяются нулями.
История переходов и дата вступления в клуб проверяются перед применением старой
карьерной базы. Числа берутся из [статистики по соревнованиям](https://highlightly.net/football-api/documentation/players/statistics/).

Полного состава клуба этот набор endpoints не предоставляет. Поэтому бот не
объявляет такую выборку всей лигой, не приостанавливает мониторинг отсутствующего
игрока и не создаёт связи автоматически. При смене клуба сохраняет историю
переходов в очередь `transfer_chain_requires_mapping`; перенос названий исторических
клубов в структурную цепочку пока требует ручного пакета и подтверждения источников.
Существующий сбор полной структурной цепочки через API-Football остаётся отдельным.

Если лимит кончился посередине списка, checkpoint хранит следующего игрока.
Следующий запуск начинает с него, затем возвращается к началу списка. Старые
ответы сохраняются в кэше (профиль и статистика — до 6 часов, таблица лиги — до
суток), поэтому повторный запуск не тратит квоту на уже свежие данные.

Dry Run готовит обычный атомарный diff карточки и `КлСтат`. `review-show`,
`review-approve` и `publish --manual` работают в выбранном провайдере.
Перед записью профиль и статистика получаются заново: изменение чисел, клуба,
личности или истории после базы отменяет публикацию. Automatic по-прежнему
требует одобрения сообщества, списка разрешённых статей и включённой публикации.
В установленном файле одобрения укажите `"providers": ["highlightly"]`, если
именно этот источник включён в согласованную задачу. Старые файлы без `providers`
разрешают только API-Football. Переключение источника не расширяет старое одобрение.

## Условия данных

В [условиях Highlightly, §6.1](https://highlightly.net/terms/) разрешены хранение,
передача и распространение данных. Это отличается от прежней неопределённости
API-Football. При этом запрет на перепродажу доступа к API, права на базы данных
и требования Wikimedia остаются отдельными условиями; разрешение не является
заявлением об открытой лицензии на все данные. Изображения бот не переносит.
