# Операции JSON 1.1

Файл `wiki_stats/update.schema.json` содержит две ветви схемы. Версия 1.0
поддерживает `update_stats`. Структурные операции
исполняются по версии 1.1. Старые зарезервированные структурные операции в
JSON 1.0 отклоняются: перенесите их в документированный 1.1.

Пакет: schema_version, package_id, generated_at (RFC3339), articles;
необязательный is_test. Статья: title, player, operations, необязательный
base_revid. Для новых пакетов обычных статей обязателен subject_scope="bundesliga":
это предоставленное оператором обозначение сферы работы, не автоматическое
исследование членства клуба. Отсутствует мониторинг других лиг. Исторические
клубы и сборные внутри выбранной статьи доступны для обработки.

У каждой операции: id, type, entity, target, as_of, sources; group_id задаёт
транзакционную группу. Без group_id операция независима. Группы внутри одной
статьи применяются к исходному снимку; их пересечение даёт patch_conflict.
Зависимые операции указывайте в одном group_id и в порядке исполнения.
Отказ любой операции отклоняет целую группу, включая ранее подготовленные патчи.

entity.name — понятное название. Для существующих строк нужен точный
entity.wikitext. Для вставки/текущего клуба задайте entity.kind (`club` или
`national_team`) и QID (`wikidata_id`) либо точную русскую статью (`page_title`).
Клубы справочника допускают известные альтернативные имена. Для сборной
обязателен age: null для основной либо число для возрастной. Ссылки и флаг
строятся после проверки QID, обратной ruwiki-ссылки, существования статьи,
страны и шаблона флага. При неоднозначности или отсутствии статьи — отказ.
Необязательные flag/display_name не обходят эти проверки.

target.structure: career или club_table. Для существующей карьеры:
target.field (`клубы`/`национальная сборная`), target.period. Селекторы точные:
флаги, внутренние ссылки, «II», аренда, возраст сборной сохраняют значение.

| type | Обязательная нагрузка операции |
|---|---|
| update_stats | expected/new с одинаковыми полями appearances/goals; season и competition |
| add_competition | Как update_stats, target=club_table; new — полный итог категории, mapping_rule обязателен при различии названий |
| add_club | payload.period, stats (оба числа), role=primary/loan/reserve; primary требует previous и связанную update_current_club |
| add_national_team | payload.period, stats; entity.kind=national_team, age; пустая/отсутствующая карьера сборных создаётся |
| update_current_club | expected — точный прежний текст текущего клуба, payload={}; новая активная строка клуба уже есть или добавлена в группе |
| update_career_period | payload.period — новый период, target.period — прежний; начальный год сохраняется |
| add_season | season; payload.categories — все категории с полной парой чисел, league_wikitext, insert_after_season, complete=true |
| update_totals | payload.complete=true; target=club_table; суммы считаются программно из целых чисел всех сезонов |
| update_date | payload.field — одно из полей даты карточки, expected_value — старое значение; новая дата берётся из as_of |

Все source.coverage_as_of должны совпадать с as_of; связанные операции имеют
единую дату охвата. Источники имеют provenance=user_provided, в отчёте
user_provided_not_independently_verified. Программа не запрашивает URL
статистических источников. Наличие URL не доказывает правильность новых чисел.

Для career update_stats клубные показатели трактуются как league/all,
сборные как national_all/all; season=null. Для таблицы scope=category,
category равна точному викитексту заголовка, например
`[[Кубок Германии по футболу|Кубок Германии]]`. Не суммируйте разные турниры
без явного mapping_rule; правило предоставлено человеком и не доказано программой.

Годы: YYYY, YYYY—YYYY или YYYY—{{н.в.}}; допустимы также – и - между годами.
Неизвестные годы и ? отклоняются. Новую историческую строку в середину
карьеры приложение не вставляет. Новая аренда/резерв сохраняет основной
клуб активным. Возвращение в ранее представленный клуб создаёт новый период.
Для primary закрывайте старую строку отдельной связанной update_career_period,
затем add_club с previous, затем update_current_club.

Новый сезон добавляется в существующий блок клуба, после последнего сезона
его последней лиги; счётчики сезонов и итоги обновляются. Сноски строки-образца
не копируются в новый сезон: такой образец безопасно отклоняется. Новый блок
клуба или новая категория требуют отдельной разработки/рассмотрения.
payload.structure_proposal в add_competition хранит предложение, которое
отображается при structure_change_required, но не публикуется.

Примеры всех операций и ошибок: examples/stage23. Все новые сведения там
вымышленные, каждый пакет явно is_test=true. Схема не допускает пароль или
токены; передавайте их только через диалог авторизации.
