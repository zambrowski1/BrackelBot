# Работа с КлСтат

Редактор поддерживает таблицы из шаблонов `КлСтат`, `КлСтат/Клуб`,
`КлСтат/Лига`, `КлСтат/Сезон`, `КлСтат/ИтогоЗаКлуб`, `КлСтат/Итого`.
Для таблиц другого формата нужен отдельный разбор.

## Проверка и сравнение

```bash
./toolforge/operator.sh check-klstat 'Участник:Zambrowski/testbot'
./toolforge/operator.sh prepare-klstat 'Участник:Zambrowski/testbot' evidence.json \
  --package-out klstat-package.json --report klstat-report.json
```

Первая команда читает таблицу, проверяет структуру, число сезонов, повторные
строки и суммы. Вторая сравнивает её с подтверждёнными данными, готовит JSON,
общий diff и план в очереди проверки. Она исправляет числа, добавляет клубы,
лиги и сезоны, пересчитывает итоги. Повторная подготовка по тем же данным
не создаёт новых изменений. Публикация выполняется отдельно через обычную
проверку плана, авторизацию и защиту от изменения исходной ревизии.

Формат `evidence.json` показан в `examples/klstat-evidence.test.json`.
Он содержит имя из карточки, дату охвата, источники и список клубов с сезонами.
Входной JSON проверяется до запросов к Википедии: обязательные поля, даты,
структура сезонов и показателей. Повторные ключи JSON, NaN и учётные данные
отклоняются. Проверки одной ссылки лиги внутри нового раздела не повторяются.
Каждый сезон должен явно содержать матчи и голы для всех категорий существующей
таблицы. Названия категорий совпадают с викитекстом заголовка, включая ссылки.
Лига задаётся одной викиссылкой. Новый клуб требует проверяемого `wikidata_id`
и совпадения `entity.wikitext` с проверенной ссылкой; `insert_after_club` выбирает
точный блок-якорь. Для существующего клуба этот якорь не нужен.

Сравнение обрабатывает только явно переданные сезоны. Пустой ответ API,
недоступный сезон или отсутствующая категория не превращаются в нулевые
показатели и не служат основанием для удаления. Дата проверки не заменяет
дату актуальности клубной статистики. Карточка, сборные и текст статьи этими
командами не изменяются. Автоматическое получение полного такого набора
из Sofascore Scraper ещё не подключено: подтверждённые данные передаются явно.

## Изменения через пакет версии 1.1

### Создание отсутствующего раздела

Та же команда `prepare-klstat` может создать раздел с таблицей, когда `КлСтат`
отсутствует. Добавьте в evidence объект `create_section`:

```json
{
  "categories": ["Чемпионат", "[[Кубок Германии по футболу|Кубок Германии]]", "Стыковые матчи"],
  "statistics_as_of": "2026-10-04",
  "full_career": false
}
```

Клубы передаются в обычном `clubs`; каждому нужна проверяемая ссылка и полные
числа всех категорий каждого сезона. Пример с вымышленными числами:
`examples/klstat-create.test.json`. `statistics_as_of` — подтверждённая дата
актуальности данных, не дата получения ответа API. Если она неизвестна,
создание раздела отклоняется. `full_career: true` задаётся оператором только
при подтверждённом полном охвате; программа сама не объявляет ответ API полным.
При `false` в разделе явно указывается диапазон переданных сезонов и неполнота
карьерного итога. Пропуски внутри диапазона не заполняются нулями.

Операция `create_statistics_section` добавляет заголовки «Статистика выступлений»
и «Клубная статистика», шаблон `обновлено`, блоки клубов и лиг, сезонные строки
и рассчитанные итоги. Она вставляет раздел перед примечаниями, ссылками и другими
заключительными разделами, либо перед категориями; при отсутствии этих якорей
добавляет в конец страницы. Сборные и карточка сохраняются. Ссылки клубов
проверяются через resolver, ссылки лиг — через Википедию. Порядок сезонов,
повторы и арифметика проверяются до формирования diff.

Существующий КлСтат, заголовки возможной статистики и обычные викитаблицы
останавливают создание нового раздела. Это консервативная проверка: иной формат
нужно сначала рассмотреть вручную. Повтор той же операции не добавляет дубль.
Создание раздела требует ручного утверждения; оно не включено в автоматические
операции. Техническая возможность не заменяет одобрение новой ботозадачи.

### Изменение существующей таблицы

У каждой операции остаются обычные `id`, `entity`, `target`, `as_of`, `sources`.
Для таблицы `target.structure` равен `club_table`, `entity.wikitext` точно
выбирает блок клуба. Связанные операции объединяются одним `group_id`.

| Тип | Дополнительные поля |
| --- | --- |
| `update_stats` | `season`, категория соревнования, ожидаемые старые и новые матчи/голы |
| `add_season` | `season`, `payload.categories`, `league_wikitext`, один якорь `insert_after_season` или `insert_before_season`, `complete: true` |
| `add_table_club` | `entity.kind: club`, проверяемый QID и викитекст; `season`; `payload.categories`, `league_wikitext`, `insert_after_club`, `complete: true` |
| `remove_season` | `season`; `payload.expected_wikitext` — весь исходный шаблон строки, `reason`, `complete: true` |
| `remove_table_club` | `payload.expected_wikitext` — точный участок от шаблона клуба до его итогов включительно, `reason`, `complete: true` |
| `update_totals` | `payload.complete: true`; пересчёт всех итогов по имеющимся строкам |

Удаления задаются отдельным пакетом явно; сравнение с источником их не генерирует.
Сначала проверяется точное совпадение удаляемого текста. При удалении сезона
уменьшаются счётчики, удаляется опустевший заголовок лиги и пересчитываются итоги.
Последний сезон клуба удаляется через `remove_table_club`. Удаление последнего
клуба, то есть всей таблицы, пока отклоняется. Сноски и комментарии в удаляемом
фрагменте также останавливают операцию. Остальные строки и текст сохраняются.

Новые структурные операции требуют ручного рассмотрения и не входят в набор
правок, допустимых в автоматическом режиме. Перед записью сохраняется резервная
копия. Любая ошибка связанной группы отклоняет всю группу.
