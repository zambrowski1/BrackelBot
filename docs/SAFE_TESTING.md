# Проверка на тестовой странице

Проводится только на `Участник:Zambrowski/testbot`. Все новые числа,
переходы и выступления Браккельманна в примерах вымышленные. Они не пригодны
для статей.

## Подготовка

1. Запустите программу через START.bat или EXE. По умолчанию выбран Dry Run.
2. Проверьте свою тестовую страницу через существующий
   `examples/BrackelBot-testbot-demo.json`. Не подтверждайте публикацию пока.
3. Нажмите «Сохранить исходную версию». Копия полученного викитекста будет
   записана в `%LOCALAPPDATA%\WikipediaStatsUpdater\backups` с номером ревизии.
   Сохраните также ссылку на ревизию в истории страницы.
4. Войдите через BotPasswords, затем выберите Manual. Смена режима очищает
   подтверждения — потребуется заново открыть diff каждой операции.

## Подготовленный полный стенд

Исходная сохранённая тестовая страница имеет три категории таблицы и не
содержит колонки еврокубков. Для всех позитивных сценариев подготовлен файл
`examples/stage23/00-comprehensive-baseline.backup.json`: копия с четвёртой
категорией «Еврокубки» и явно синтетическими нулями. Это специальный стенд,
а не автоматическое заполнение неизвестной спортивной статистики.

Чтобы поставить стенд, нажмите «Восстановить из копии», выберите этот файл,
просмотрите **весь diff**, подтвердите операцию и только затем нажмите
«Опубликовать утверждённое» в Manual. Таким образом установка стенда — тоже
ручная правка тестовой страницы. Разработчик её не выполняет самостоятельно.
При подготовке проекта полный стенд не загружался на Википедию.

Перед каждым независимым сценарием восстанавливайте полный стенд через тот
же просмотр и подтверждение. Подставлять другой исходный текст молча нельзя.
Если страница отличается, операция может корректно отказать с несовпадением.

## Сценарии из examples/stage23

| Файл | Ожидаемый результат на полном стенде |
|---|---|
| 01-update-stats.json | Карточка: Аугсбург 4 (1) → 5 (2); посторонний текст сохранён |
| 02-transfer.json | Закрытие Аугсбурга, новая строка мёнхенгладбахской Боруссии, текущий клуб; одна группа |
| 03-add-national-team.json | Новая Германия U21 без объединения с U18/U19 |
| 04-career-period.json | Подтверждённое изменение конечного года исторического периода |
| 05-add-season.json | Новый сезон в уже существующем блоке Падерборна, счётчики сезонов и итоги |
| 06-europe-existing-category.json | Тестовый еврокубковый итог Аугсбурга в существующей категории |
| 07-combined-atomic.json | Все изменения в одной группе; нужно подтвердить каждую изменяемую операцию |
| 08-mismatch-rolls-back-all.json | old_value_mismatch; вся связанная группа отклонена, пустой общий diff |
| 09-repeat-after-01.json | После успешного 01: already_applied; без новой публикации |
| 10-structure-proposal.json | Предложение новой колонки; requires review, исполнимых патчей нет |
| 11-incomplete-statistics.json | Неполные категории нового сезона; отказ, без подстановки нулей |
| 12-unknown-years.json | Неизвестный конечный год; отказ |
| 13-wrong-borussia-qid.json | Название Мёнхенгладбаха и QID Дортмунда несовместимы; группа отклонена |
| 14-recompute-totals.json | На согласованном стенде already_applied; при известных неверных итогах пересчёт |
| 15-confirmed-coverage-date.json | Только указанное поле даты: дата охвата источников, не часы компьютера |

В позитивном сценарии: загрузить → проверить → выбрать каждую строку →
показать изменения → подтвердить. При нескольких операциях одной группы
публикация запрещена до подтверждения всех изменяемых членов. Если один член
ошибочен, группа целиком отклонена. Одно сохранение страницы включает все
выбранные группы; частичных сетевых записей внутри группы нет.

После публикации загрузите тот же пакет и выполните проверку ещё раз:
показатели должны быть already_applied, повторной правки не требуется.
JSON-отчёт можно экспортировать на каждом шаге.

## Конфликт ревизий и запреты

После просмотра diff измените тестовую страницу вручную в браузере, затем
попробуйте опубликовать старый план. Ожидается revision_conflict, сброс
подтверждений и запрет старого плана. Нужны новая проверка и новый просмотр.
Если изменение произошло между повторной проверкой и POST, `baserevid` и
`basetimestamp` защищают от перезаписи новой версии.

Статьи основного пространства допускают Dry Run, но публикация в них
запрещена непосредственно Publisher и API-клиентом. Automatic недоступен.
Оба запрета проверены локальными тестами; не пытайтесь экспериментировать
с реальным сохранением в основном пространстве.

Если при отправке пропал ответ, статус publication_unknown означает, что
результат записи неизвестен. Запрос не повторяется автоматически. Проверьте
историю страницы, затем загрузите текущую ревизию заново.

## Восстановление

Для восстановления вашего исходного состояния выберите копию, которую вы
сохранили **до испытаний**. Программа получит текущую ревизию, покажет полный
diff, потребует подтверждение и применит восстановление только к тестовой
странице с защитой конфликтов. До каждого сохранения автоматически создаётся
ещё одна копия текущего состояния.

Файл `99-original-testbot.backup.json` — исходный снимок, полученный при
разработке (номер ревизии внутри файла). Он полезен для стенда, но ваша более
новая исходная копия имеет приоритет. Восстановление заменяет весь текст
тестовой страницы: внимательно проверьте diff, чтобы не потерять свои новые
не относящиеся к испытанию правки. Перенос файла резервной копии в JSON-пакет
не разрешает восстановление другой страницы.
