# Работа бота с СбМатчи

JSON версии 1.1 поддерживает `update_sbmatch` (исправление существующего
матча) и `add_sbmatch` (добавление в конец существующего списка).
Пакет можно загрузить в GUI через «Загрузить JSON» или в серверный CLI
через `import-json`. Дальше используются обычные diff, подтверждение,
повторная проверка ревизии и публикация.

## Выбор таблицы и матча

У статьи должны быть единственная карточка `Футболист` с совпадающим именем
и существующий шаблон `СбМатчи` (также принимается `Шаблон:СбМатчи`).
`entity.kind=national_team`, а `entity.wikitext` должен точно совпасть с
параметром `сборная`, включая ссылку и её подпись.
`target.structure=sbmatches`, `target.age` — целое число из `возраст`
или `null`, если возраст не задан. `target.match_index` — номер строки.
Если подходят две таблицы, бот отказывается от изменения.
В статье обязателен `base_revid`.

`payload.match` содержит строки `дата`, `соперник`, `счёт`, `голы`,
`соревнование` и необязательную строку `пенальти`. Для исправления нужен
также `payload.expected_match` со всеми исходными полями (соревнование
указывается и при наследовании из общего параметра шаблона).
Для удаления серии пенальти передайте пустую строку `пенальти`.
Счёт указывается от лица сборной игрока.

Даты поддерживают `ДД-ММ-ГГГГ`, `ДД.ММ.ГГГГ` и `ГГГГ-ММ-ДД`. Порядок строк — по датам.
Голов игрока не может быть больше голов сборной. Пенальти допустимы
только после ничьей; итог серии не может быть ничейным.
Новый матч не может быть позже `as_of`. `sources` и дата охвата обязательны.
Нельзя передавать шаблоны, HTML или разделители параметров в новых полях;
обычные викиссылки допускаются.

## Что сохраняется и изменяется

Поддерживаются `матчN=дата ;; соперник ;; счёт ;; голы [;; соревнование]`
и подробные поля `датаN`, `соперникN`, `счётN`, `голыN`, `соревнованиеN`.
Исправление сохраняет формат строки; новый матч использует формат последней.
Существующие источники, сноски и окружающий текст сохраняются.
У нового матча создаётся `источникN` со ссылкой из первого элемента `sources`.
Существующий `обновлено` продвигается до даты охвата и не уменьшается.
Если его нет, параметр автоматически не создаётся.
Итоги не записываются ботом: их пересчитывает Lua-модуль при отображении.

Повторное применение готовой операции возвращает `already_applied`.
При неверной ревизии, несовпадении старого матча, пропущенных номерах,
неизвестных параметрах или дублировании матча добавление отклоняется.
Связанные через `group_id` операции применяются целиком либо не применяются.

## Проверка без сети

Примеры в `examples/sbmatches/` полностью синтетические. Каждый пример
рассчитан на исходный снимок из подкаталога `fixtures`:

```powershell
.\.venv\Scripts\python.exe -m wiki_stats.cli examples/sbmatches/update_sbmatch.test.json --fixtures examples/sbmatches/fixtures --report sbmatches-report.json
.\.venv\Scripts\python.exe -m wiki_stats.cli examples/sbmatches/add_sbmatch.test.json --fixtures examples/sbmatches/fixtures --report sbmatches-add-report.json
```

В GUI: загрузить JSON → проверить → показать изменения → подтвердить.
Синтетические пакеты нельзя использовать для настоящих статей.
Для сетевого теста сначала подготовьте свою тестовую страницу и замените
`base_revid` на её текущую ревизию.

GUI по-прежнему записывает только на `Участник:Zambrowski/testbot` и `testbot1`–`testbot5` того же участника.
Серверная запись в статьи требует одобрения задачи и явного включения
`update_sbmatch` / `add_sbmatch` в список разрешённых операций.
Эти операции требуют индивидуального подтверждения; Automatic их не выполняет.

Команда Sofascore `prepare-player` получает матчи основной сборной, сверяет
полный список с итоговой статистикой и обновляет карточку. В режиме с 2020/21
она создаёт отсутствующий СбМатчи; создание не перезаписывает существующую таблицу.
Пакет содержит источники каждого матча. Неполный список не выдаётся за полный.

Столбец выбирается в шаблоне: `статистика=голы` (по умолчанию) либо `статистика=пропущенные голы`. В JSON строки передавайте соответствующее поле `голы` или `пропущенные голы`: положительное число в строке, пустую строку либо не передавайте поле. Пустое значение и 0 отображаются модулем как 0; бот не записывает тире вместо числа. Значение другого столбца отклоняется, чтобы не потерять данные. Пропущенные голы проверяются по счёту соперника. В кратком формате четвёртое поле относится к выбранной статистике. Итоги вычисляются по выбранному столбцу.


## Полный список из API

`prepare-player` для Sofascore подключает сборщик основной мужской сборной и создаёт операцию `reconcile_sbmatches` для существующего шаблона. Нужны полный подтверждённый список, совпадение итогов API и сопоставление всех старых матчей по дате и личности соперника. Новые встречи можно вставить и в начало списка. Старые ссылки на соперников, названия соревнований, примечания и сноски сохраняются. Удаление непарной старой строки запрещено. Пакет связан с ревизией и контрольными суммами шаблона и его даты.

Дополнительные поля строки: `место`, `передачи`, `минуты`, `примечание`. Они поддерживаются при чтении, создании, исправлении и полном сопоставлении. При точечном исправлении неуказанные дополнительные поля сохраняются; явная пустая строка очищает поле. Для старого списка с нехронологическим порядком предусмотрено `порядок=исходный`. Новые списки по умолчанию идут по датам.

Для старой обычной таблицы сначала используется [перенос](NATIONAL_TABLE_MIGRATION.md). Основная команда не создаёт новый шаблон рядом с неразобранной старой статистикой. Женские и молодёжные списки не подменяются взрослыми мужскими данными.


В полном цикле Sofascore ссылки на отдельные матчи остаются в пакете проверки, но не вставляются в ячейки соревнования. Общая ссылка на профиль игрока выводится во втором параметре внешнего `Обновлено`; если дата внутри `СбМатчи`, для неё служит `источник`. Старые редакторские сноски сохраняются. Нулевые голы отображаются цифрой `0`.
