# Общий каталог сезонов лиг

Цель — искать статьи сезонов **всех футбольных лиг**, включая низшие дивизионы и женские чемпионаты, с начальным годом 2010 до текущего года. Ограничения по странам нет. Это каталог существующих статей русской Википедии, а не список сезонов, по которым Sofascore предоставляет статистику.

Два источника дополняют друг друга:

1. Action API Википедии: категории сезонов и национальных футбольных чемпионатов, их подкатегории и страницы. Все продолжения ответов обрабатываются; каждый ответ сохраняется. После ограничения частоты выполняется ожидание, учитывающее `Retry-After`. После пяти ограниченных попыток обход прекращается, кеш сохраняется.
2. Wikidata: русские статьи спортивных сезонов, связанные через `P3450` с футбольным соревнованием (`P641 = Q2736`). Дополнительный запрос читает все русские статьи сезонов найденных соревнований без требования к типу самого сезона. Само наличие связи не доказывает, что соревнование — лига: проверяются типы `P31` и предки `P279`. Дополнительное основание — категория национального чемпионата или дивизиона. Если тип соревнования в Wikidata общий, связь с другой его сезонной статьёй используется только при совпадении точного названия лиги с названием из подтверждённой категории; общий объект чемпионатов страны не подходит. Кубки и международные турниры исключаются; неподтверждённые случаи идут в `review.json`.

`wiki_stats/season_catalogue.json` содержит точные названия, сезоны, идентификаторы лиг, страны и основания включения. `handoff/season-catalogue/catalogue.csv` предназначен для просмотра; `coverage.csv` показывает найденные статьи по лигам и годам. Пустая строка покрытия означает «не найдено этим поиском», а не «статьи нет». В снимке объектов Wikidata сохранены названия, русские ссылки и нужные утверждения `P31`, `P279`, `P17`, `P641` со своими источниками; остальные свойства не нужны для проверки каталога.

Бот ищет точное сочетание лиги и сезона в каталоге перед прежними вариантами названий. Альтернативные названия лиг добавляются только по сохранённым ответам API о перенаправлениях на конкретную статью лиги. При нескольких статьях одного года (например, Апертура и Клаусура) каталог не выбирает произвольную. Перед включением ссылки в правку существование страницы всё равно проверяется через API. Календарные сезоны, переходные сезоны, разные дивизионы и мужские/женские соревнования не смешиваются.

Полный обход найденных корневых категорий не доказывает, что найдена каждая статья Википедии: страницы без подходящих категорий и связей Wikidata могут остаться вне поиска. Поле `category_traversal_complete` сообщает именно о завершении обхода, а не о стопроцентном покрытии всей энциклопедии. Компилятор по умолчанию отказывается выпускать результат без завершённого обхода. `--allow-incomplete` предназначен для промежуточной проверки и сохраняет признак неполноты.

Повторить сбор и проверку:

```powershell
.\.venv\Scripts\python.exe -X utf8 tools/build_season_catalogue.py
.\.venv\Scripts\python.exe -X utf8 tools/query_season_wikidata.py
.\.venv\Scripts\python.exe -X utf8 tools/fetch_season_league_entities.py
.\.venv\Scripts\python.exe -X utf8 tools/query_related_league_seasons.py
.\.venv\Scripts\python.exe -X utf8 tools/compile_season_catalogue.py
.\.venv\Scripts\python.exe -X utf8 tools/fetch_season_league_redirects.py
.\.venv\Scripts\python.exe -X utf8 tools/compile_season_catalogue.py
.\.venv\Scripts\python.exe -X utf8 tools/check_season_catalogue.py
```

Сетевые команды запускайте последовательно. Обход возобновляется из сохранённых ответов. Для воспроизведения завершённого обхода без сети добавьте `--offline` к первой команде; запрос Wikidata и загрузку объектов при этом повторять не нужно. Проверка и компиляция работают без сети. Футбольный API не вызывается, изменений в Википедии эти команды не делают.

Кеш предназначен для продолжения и воспроизведения одного снимка, а не для автоматического получения свежих ответов. Перед новым полным сбором сохраните прежнюю папку `handoff/season-catalogue` и начните с чистой папки на этом месте. Сначала соберите новые ответы и объекты Wikidata, затем скомпилируйте каталог. Перезапустите работающий процесс бота после замены каталога.
