# Sofascore Scraper

Адаптер использует Sofascore Scraper от OmkarCloud через RapidAPI. API-Football
и Highlightly остаются отдельными источниками: их ID, квоты и реестры не смешиваются.

Ключ хранится в `SOFASCORE_API_KEY`. На Toolforge:

```bash
toolforge envvars create SOFASCORE_API_KEY
```

Введите ключ в приглашении. Для подготовки diff не нужны пароль Википедии и
включение публикации. Старые задания сбора можно оставить приостановленными.

Несколько независимых подписок задаются через `SOFASCORE_KEYS`, JSON-массив
строк. Этот параметр имеет приоритет над `SOFASCORE_API_KEY`:

```bash
toolforge envvars create SOFASCORE_KEYS
# В приглашении: ["ключ-первой-подписки", "ключ-второй-подписки", "ключ-третьей-подписки"]
toolforge jobs run bb-sofa-keys --image python3.13 --command './brackelbot/toolforge/operator.sh --provider sofascore check-api' --wait
tail -n 60 ~/bb-sofa-keys.out
```

На Toolforge `check-api` запускайте через Jobs, как показано ниже для подготовки
diff. Он делает по одному запросу профиля на доступный ключ, проверяя доступ
и заголовки квоты. `api-quotas` показывает сохранённые остатки без запросов API.
Три подписки по 1000 дают суммарный лимит 3000 за их окна подписки. Остатки
и сроки сброса хранятся отдельно для каждой; старый счётчик первого ключа
при добавлении новых сохраняется. Несколько ключей одного аккаунта не считаются
независимыми подписками и не должны перечисляться таким способом.

Запросы расходуют первый доступный ключ, затем следующий. При исчерпании квоты
(включая HTTP 429 с нулевым остатком) или отклонении ключа HTTP 401/403 бот
переключается на следующую подписку. Ограничение частоты с ненулевым остатком
останавливает весь пул на период ожидания. Сетевые ошибки и HTTP 5xx не
вызывают переключения или автоматического повтора. Кэш общий для всех ключей.
В отчёты попадают номера слотов и отпечатки, сами ключи не сохраняются в базе.

```bash
toolforge jobs run bb-sofascore-preview --image python3.13 --command './brackelbot/toolforge/operator.sh --provider sofascore prepare-player 1128792 --title Участник:Zambrowski/testbot --identity-title "Браккельман, Кальвин" --qid Q114406918 --wiki-name "Кальвин Браккельман" --package-out ../reports/sofascore-package.json --report ../reports/sofascore-report.json' --wait
tail -n 80 ~/bb-sofascore-preview.out
tail -n 30 ~/bb-sofascore-preview.err
```

Для другого футболиста замените Sofascore ID, QID, статью и имя карточки.
`--title` допускает связанную статью или тестовую страницу. В тестовой карточке
проверяются имя и дата рождения. QID, статья и дата рождения дополнительно
сверяются с Википедией и Wikidata; поиск по имени не создаёт связь автоматически.

Команда получает профиль, сезоны, статистику, историю переходов и страницы матчей,
сравнивает карточку и КлСтат, сохраняет пакет, отчёт и план для `review-show`.
Правки в Википедию она не отправляет. Для нового источника пока нет автоматической
публикации в основном пространстве и фонового обхода всех игроков через `run`.

## Что проверяется

В обычном режиме (с первым сезоном 2020/21) бот копирует готовые сезонные
показатели Sofascore. Игрок, клуб, сезон и турнир по-прежнему сверяются;
пересчёт каждого матча для принятия обычного сезонного итога не требуется.
При переходе внутри сезона сохраняется проверка разбивки по клубам.
История матчей нужна отдельно для даты актуальности и матчей сборной.
Если дату матча установить не удалось, сезонная таблица всё равно создаётся,
но новая дата актуальности не подставляется.

Если одной категории нет в ответах, остальные числа сезона всё равно
вставляются. В новой ячейке ставится `—`, в существующей сохраняется прежнее
значение. Явный ноль в источнике остаётся нулём. Неполный новый итог — `—`;
числовой старый итог сохраняется до появления полного набора данных.
Причины пропусков записываются в отчёт, а не в текст статьи.
Значение `null` в JSON новой клубной строки означает неизвестную категорию;
для такой строки нужен `allow_unknown: true`. В карточке `null` не допускается.

Строка «Итого» неполного блока выводится обычной строкой викитаблицы внутри
КлСтат. Это позволяет оставить тире в суммарных графах: стандартный
`КлСтат/ИтогоЗаКлуб` не передаёт явно заданные суммарные значения во вложенный
шаблон и иначе выводит вопросик. Бот распознаёт собственные строки итогов
при повторном запуске и умеет заполнять ранее неизвестные ячейки.


- Чемпионаты Германии: Bundesliga, 2. Bundesliga, 3. Liga, Regionalliga Nord/West.
  Кубок Германии сопоставляется только с явно известной колонкой кубка.
- Игры и голы сравниваются отдельно для клуба, сезона и категории. Изменение
  строки КлСтат пересчитывает итоги. Неизвестные показатели не заменяются нулями.
- В обычном режиме новая строка содержит все известные категории, неизвестные
  обозначаются длинным тире. Старый режим полной сверки по матчам требует
  данных для всех колонок.
  Удалений по отсутствию строки в API нет. Если раздела нет, можно создать
  таблицу доступных сезонных показателей с тире в неизвестных графах.
  Пометки о неполноте остаются в отчёте, полного карьерного итога
  ограниченная выборка не заявляет.
- Карьерный итог требует непрерывного ряда подтверждённых сезонов за один клуб.
  Простой летний переход можно связать с закрытием старого периода, добавлением
  нового клуба и изменением текущего клуба. Зимние переходы, возвращения,
  аренды и пропущенные промежуточные клубы требуют отдельного разбора.
- Номер меняется только вместе с подтверждённым текущим клубом. Неизвестный
  номер пропускается; комментарии и ссылки рядом с числом сохраняются.
- Дата берётся из завершённого матча с подтверждёнными минутами участия.
  Будущие встречи, товарищеские матчи и пребывание на скамейке не подходят.
  Нужна полная пагинация. Старая дата не заменяется более ранней.
  Общая дата карточки требует покрытия всей клубной карьеры; дата таблицы —
  всех её категорий. Дата получения ответа API не подставляется вместо даты матча.
- Основные сборные сверяются по полной истории матчей и общему итогу источника.
  Молодёжные показатели сохраняются до отдельного подтверждения их охвата.

У поставщика параметр `regularSeason` может возвращать 404. Тогда адаптер
пробует `overall`. В обычном режиме принимается явный итог поддерживаемого
турнира за нужный сезон и клуб. В старом режиме полной сверки по матчам
дополнительно требуется совпадение с полной историей выступлений.

## Квота и ограничения

Бесплатный лимит — до 1000 запросов за окно подписки. Адаптер учитывает
`X-RateLimit-Requests-Limit`, `Remaining`, `Reset` и хранит остаток в базе.
До получения заголовков разрешён только один диагностический запрос.
Неуспешный запрос тоже резервирует квоту. При исчерпании новые запросы
останавливаются; платное превышение и автоматические повторы не используются.
Кэш не расходует дополнительные запросы.

`--max-statistics` ограничивает число проверяемых записей сезонов (по умолчанию
100; fallback может потребовать второй запрос). `--max-match-pages` ограничивает
пагинацию (30 страниц по умолчанию). `--max-match-requests` ограничивает обращения
к статистике, составам и событиям матчей, включая чтение кэша: по умолчанию 512,
допустимы значения от 0 до 2000. Ноль отключает восстановление по матчам.
Меньшие лимиты можно задавать явно; при остановке частичный итог сезона не
подставляется. Эти границы не заменяют защиту бесплатной квоты каждого API-запроса.
Остаток квоты и причины пропусков находятся в `collection` отчёта.

Отсутствующий в индексе турнир восстанавливается только для закрытого сезона:
нужны полная история, подтверждённая связь с клубом через другой турнир этого
сезона и проверенные составы и события всех соответствующих матчей. Еврокубковая
графа включает квалификацию и поддерживает иностранные клубы; она не проверяется,
если такой графы нет в таблице. Нулевое число выходов можно подтвердить составами,
но отсутствие ответа или записи в индексе само по себе не означает ноль.

Если личная история начинается посреди закрытого сезона, кубковую графу можно
проверить по полному календарю турнира. Сезон выбирается из
[`/tournaments/seasons`](https://www.omkar.cloud/tools/sofascore-scraper/tournament-seasons),
а все страницы матчей — из
[`/tournaments/matches`](https://www.omkar.cloud/tools/sofascore-scraper/tournament-matches).
Для каждого матча клуба проверяются подтверждённые составы и события.
Отсутствие игрока допускает ноль только при наличии всех 11 стартовых игроков
обеих команд, уникальных идентификаторов, полной ленты голов и отсутствии
противоречащих событий с этим игроком. Если игрок отсутствует во всём полном
подтверждённом протоколе, его отсутствие проверяется независимо от полноты
ленты голов: незаявленный игрок не может участвовать по
[правилу 3 IFAB](https://theifab.com/laws/latest/the-players/).
Названный запасной требует проверки событий. Противоречащее событие с игроком
блокирует вывод нуля. В отчёте отдельно перечислены такие подтверждения по
протоколам. Частичный календарь, неправильный сезон,
неподтверждённый состав или исчерпанный лимит не дают частичного итога.

Для сезонов 2009/10–2020/21 аналогично проверяются полные календари Лиги
чемпионов и Лиги Европы. Общая графа принимается только после проверки обоих
турниров. После появления Лиги конференций в 2021/22 такая проверка двух
турниров не подтверждает всю еврокубковую графу. Открытые сезоны этим способом
пока не восстанавливаются. Каждый запрос календаря учитывается и в лимите
восстановления, и в защите бесплатной квоты API. Сезон определяется явным ID и
годами из индекса турнира; допустимый период включает июль и август следующего
года, чтобы перенесённые финалы 2019/20 не считались чужим сезоном. Восстановление
закрытого календаря допускается после 1 сентября следующего года.

```bash
./brackelbot/toolforge/operator.sh --provider sofascore api-quotas
```

Техническое подключение не подтверждает права на распространение данных.
Проверка условий источника и одобрение ботозадачи остаются отдельными условиями
эксплуатации; публикация по умолчанию выключена.

Документация поставщика: [Player statistics](https://www.omkar.cloud/tools/sofascore-scraper/player-statistics),
[Player matches](https://www.omkar.cloud/tools/sofascore-scraper/player-matches).

При выборе типа статистики используется statistics_types из ответа statistics-seasons. Для поддерживаемых идентификаторов лиг объявленные overall/home/away означают статистику указанного чемпионата; запрос regularSeason для таких сезонов не выполняется. Если метаданные отсутствуют или содержат playoffs, сохраняется проверка по полной истории матчей. Наблюдаемые стыковые матчи не перекрываются метаданными. Ошибка доступности одного сезона не останавливает независимые запросы; квота, блокировка доступа и ограничение частоты останавливают сбор.

Для графы «Еврокубки» поддерживаются турниры 7 (Лига чемпионов) и 679 (Лига Европы); суммы относятся к одному клубу и сезону. Ошибка одного ответа или остановка до сбора всех нужных турниров запрещает применение частичной суммы. Прочие турниры остаются явно отмеченными в диагностике, неизвестные значения не заменяются нулями.

Еврокубковый ответ сверяется с полной историей выступлений в турнире и
сезоне, включая квалификацию с отдельным идентификатором сезона. Несовпадение
числа матчей или неизвестные минуты участия запрещают замену общей графы
неподтверждённым итогом основного раунда.

Если в сезоне был переход, число матчей в статистике чемпионата должно
совпасть с полной историей выступлений именно за указанный клуб.
Подпись `team` в сезонном ответе сама по себе не разрешает перенос общего
итога нескольких клубов в одну строку. Несовпадение сохраняет старое значение.

Дублирующиеся строки существующего сезона и карьеры исправляются отдельными операциями repair_duplicate_season и repair_career_duplicates. Нужна точная ревизия и ожидаемые старые показатели. Из разных неподтверждённых ячеек значение не выбирается; совпадающие старые ячейки могут сохраняться с предупреждением. Сноски и комментарии внутри удаляемого дубликата останавливают правку. Для периода YYYY—? допускается восстановление текущего конца по подтверждённой дате прихода, профилю нынешнего клуба и отсутствию последующего ухода; начальный год не изменяется.

Подпись `(аренда)` сохраняется при сопоставлении сезона с API. Несколько
недостающих сезонов вставляются последовательно: каждая следующая строка
может использовать уже добавленный сезон как якорь. Альтернативная подпись
клубной ссылки сравнивается по проверенному QID.

Для закрытого сезона нулевые значения отсутствующей графы допускаются
только при полной истории матчей, охватывающей границы сезона, и точном
совпадении числа выступлений в чемпионате со статистикой API. Если в
нужном турнире есть выступление или неизвестны минуты участия, ноль
не выводится. Открытый сезон по этому правилу не заполняется нулями.
Турнир 799 используется как подтверждённая статистика Суперкубка Германии
в графе «Прочие»; неоднозначные и неподдерживаемые турниры остаются в отчёте.

Если сезонный итог смешивает клубы или не включает квалификацию еврокубков,
бот может пересчитать нужную графу через `/matches/player-statistics`.
История матчей должна быть полной, с проверяемой командой, датой и участием
игрока. Каждый ответ обязан подтвердить матч, игрока, клуб, минуты и явное
значение `goals` либо `goals_conceded`. Отсутствующее поле не означает ноль.
По умолчанию общий лимит восстановления составляет 512 обращений за прогон,
включая чтение кэша; квоты адаптера продолжают действовать. Частичный пересчёт не применяется. Идентификаторы
матчей сохраняются в диагностике и примечании источника пакета.

Для отсутствующих личных показателей разрешены подтверждённые составы и
полная лента событий `/matches/lineups` + `/matches/incidents`. Конечный
счёт ленты должен совпасть с матчем, а все голы — образовать последовательность
от 0:0 до этого счёта. Автоголы не включаются в голы игрока. У вратаря
учитываются только голы соперника во время его участия; гол в минуту замены
без однозначного порядка событий останавливает пересчёт. Скамейка без выхода
не становится сыгранным матчем. Исторический team_id в записи состава может
отражать нынешний клуб игрока: принадлежность определяется стороной матча,
подтверждённым составом и идентификатором игрока.
Лимит восстановления настраивается от 0 до 2000; учёт подписок и запрет
платного превышения сохранены.

Сборщик `collect_national_scope` отдельно проверяет полный список матчей
основной сборной. Нужны полная личная история, итог сборной для того же игрока
и команды и подтверждение каждого завершённого матча. Будущие матчи исключаются;
итог выступлений и забитых голов должен совпасть с общим ответом источника.
Для вратаря поле `goals` общего ответа означает забитые голы: пропущенные
получаются только из отдельно проверенных матчей и записываются с минусом.
Частичный список или несовпадение итогов останавливает экспорт всей сборной.
Отсутствие игрока в полном подтверждённом составе может исключить матч из
списка; отсутствие личной статистики само по себе этого не доказывает.
Сборщик подключён к основному циклу: подтверждённый итог обновляет единственную
строку основной сборной в карточке, если подтверждён её период. Отсутствующий СбМатчи создаётся по полному подтверждённому списку. Дата сборной в карточке берётся по последнему подтверждённому матчу. Молодёжные строки не препятствуют обновлению этой даты; их цифры сохраняются. Если поле даты отсутствует, бот добавляет его. Дата обращения к источнику хранится отдельно.

Для графы «Прочие» в немецком сезоне 2026/27 действует отдельная проверка:
полный календарь Суперкубка должен исключать участие клуба, календарь чемпионата
и личная история должны совпасть по его матчам и числу выступлений. Опубликованный
календарь DFL подтверждает отсутствие стыковых матчей до 27 мая 2027 года.
Проверка прекращает действовать в эту дату и не переносится на другие сезоны.
Telekom Cup 2026 исключается как товарищеский турнир по официальному отчёту
«Баварии». Неизвестный турнир, неполный календарь или конфликт данных не дают нуля.
Источники DFL и клуба записываются отдельно от ответов Sofascore.

Для неполной ленты старого кубкового матча можно приложить независимый
протокол DFB: `secondary_match`, ключ — идентификатор матча Sofascore,
значение содержит `url` и исходный `html`. Адаптер не доверяет готовым числам
из этой записи: каждый раз проверяет канонический адрес DFB, дату, сезон,
счёт и полное совпадение обоих составов. Игрок должен быть запасным в обоих
источниках; три разрешённые замены должны быть отданы трём другим игрокам.
Этот способ ограничен Кубком Германии 2009/10–2015/16: четвертую замену
в дополнительное время DFB ввёл в сезоне 2016/17
([официальные сообщения DFB](https://www.dfb.de/fileadmin/_dfbdam/126236-OM_09_2016_Final.pdf)).
Два выхода на замену, неполный состав, расхождение источников или более
поздние правила не подтверждают отсутствие участия. Ссылка и вид доказательства
сохраняются отдельно от ответов Sofascore в диагностике и пакете правок.

Намеренно вымышленный СбМатчи на назначенном полигоне Орбана можно заменить
двумя матчами из подтверждённых составов и лент событий. Это операция
repair_sbmatches с SHA256 исходного шаблона и точной ревизией. Заголовок
обязательно начинается «Полигонная выборка:». Она запрещена в обычных статьях
и не заменяет сбор полных данных сборной. Параметры вне известной структуры,
сноски и комментарии внутри заменяемого шаблона требуют ручного рассмотрения.
# Все доступные сезоны

Команда `prepare-player` по умолчанию берёт все доступные сезонные показатели (`--statistics-since 0`). Она не пересчитывает их по отдельным протоколам. При необходимости можно задать первый сезон, например `--statistics-since 2020`; более ранние строки тогда сохраняются. Новая таблица содержит сноску на профиль футболиста Sofascore во втором параметре `{{обновлено|дата|сноска}}`. При сборе всех доступных сезонов добавляется строка «Всего за карьеру» через `{{КлСтат/Итого}}`; её числа складываются из показанных сезонных значений. В новых строках КлСтат недоступные категории показываются нулями по просьбе пользователя. Итоги считаются по показанным значениям; исходные пропуски остаются в пакете и отчёте.

Клубные итоги карточки содержат только чемпионаты. Если задан первый сезон обновления, сохранённые более ранние строки КлСтат прибавляются к новым сезонным показателям ровно один раз. При пропуске сезона итог карточки сохраняется: неполная сумма не заменяет полный период. Для вратарей используются пропущенные голы со знаком минус.

Если подтверждён полный список матчей основной сборной, бот создаёт отсутствующий СбМатчи. Существующую таблицу он меняет только при однозначном сопоставлении сборной и сохранности сносок и комментариев. Команда готовит пакет и diff; публикация выполняется отдельно.

В новой КлСтат заголовки «Кубки», «Еврокубки» и «Прочие» получают сноски `{{efn|…}}` со ссылками на вошедшие в таблицу турниры. Например, «Кубки» могут поясняться как «Кубок Германии», а «Еврокубки» — как «Лига чемпионов УЕФА, Лига Европы УЕФА». Для турнира без записи в справочнике ссылка не придумывается. Сноски выводятся через `{{комментарии}}`. При обновлении готовой таблицы бот сохраняет её пояснения и скрытые комментарии.



Полный API-цикл «СбМатчи», сохранение редакторских примечаний и проверка конфликтов описаны в [инструкции](SBMATCHES.md). Результаты проверки 50 разных статей — в [отчёте](FIFTY_ARTICLE_FORMATS.md).


Проверка трёх статей 12 октября выявила дополнительные случаи. Для Крамарича добавлены HNL (ID 170), Кубок Хорватии (307) и старые названия колонок «Кубок страны»/«Остальные». Возврат из аренды перед постоянным приходом в том же году не закрывает более поздний действующий период; дата карточки не продвигается, если его числа не подтверждены.

Из истории сборной исключаются матчи против явно обозначенного клуба (пример: Хорватия — «Омиш»), с сохранением ID исключений в отчёте. Неизвестный флаг команды не считается клубом. Затем обязательно сверяются число выступлений и голы всего списка с итогом API. Для серии пенальти после двух матчей нужен явный ничейный общий счёт, номер первого матча, два матча в раунде и согласованные показатели счёта. Отдельная игра может завершиться не вничью: её результат сохраняется, а сумма и серия записываются в примечание СбМатчи.

Период основной сборной не закрывается по последнему матчу. Если указан только начальный год, бот добавляет `{{н. в.}}`. Явный конечный год сохраняется; период открывается снова только при подтверждённых дополнительных выступлениях либо матче после конечного года. Исправление одних голов не меняет период. Молодёжные сборные обрабатываются отдельно.
