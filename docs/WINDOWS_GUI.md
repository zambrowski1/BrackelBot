# BrackelBot 0.4 — Windows и серверный цикл для Toolforge

Продолжение существующего проекта. Этапы 2–3 сохранены; добавлены официальный
клиент API-Football, справочники ID, карьерные базы, постоянное хранилище,
очередь проверки и CLI без Qt. Ключи передаются через окружение/Toolforge Envvars.

**На Toolforge проект ещё не развёрнут.** API-Football аккаунт у оператора есть,
но ключ в этой среде не задан: тариф и живые ответы не проверялись. Реальных
публикаций и подачи заявки на статус бота не было. Результаты фактических
автоматических запусков — verification-server.txt.

## Быстро начать

- Windows GUI: распаковать Windows ZIP и открыть START.bat.
- Проверить свой API без правок: CHECK_API.bat из архива исходников.
- Обычные тесты: TEST.bat; серверная установка без GUI: TEST_SERVER.bat.
- Сервер: `python -m pip install ".[server]"`, затем
  `python -m wiki_stats.server_cli --help`. PySide6 не является обязательной
  зависимостью core/server; для GUI есть extra `.[gui]` и requirements.txt.
- Начальный режим — Dry Run; учётные данные сами по себе не включают публикацию.

## Ограничение публикации

Локальный Publisher по умолчанию разрешает только testbot. Серверный Publisher
использует тот же код проверки и патчей, дополнительно проверяя policy.
В Test сохраняется жёсткое имя testbot. В основном пространстве нужны:
реальное одобрение сообщества, явные статьи/операции/сезоны, включение оператором,
выключенный аварийный блокировщик, свежие подтверждённые источники и ревизия.

Automatic генерирует низкорисковые числовые обновления существующих строк.
Новые клубы, сборные, периоды, неизвестные сезоны/соревнования идут на ручную
проверку. Сезонные числа никогда напрямую не заменяют карьерные: нужна
подтверждённая база и дельта. Официальное одобрение не снимает все ограничения.

Новые файлы: `wiki_stats/api_football_client.py`, `player_registry.py`,
`club_registry.py`, `statistics_engine.py`, `state_store.py`, `operator_review.py`,
`scheduler.py`, `publication_policy.py`, `server_cli.py`, `approval.schema.json`,
`toolforge/`, `examples/server/` и тесты API/сервера. JSON 1.1 принимает дополнительное
provenance=api_football; само это поле не означает независимую проверку источника.
Сервер проверяет отдельное происхождение плана в постоянном хранилище.

# Локальная программа и сохранённые этапы 2–3

Продолжение существующего Wikipedia Stats Updater. Локальная бесплатная программа
для Windows 10/11 и Python 3.12+. PySide6, mwparserfromhell, jsonschema, requests.
Локальный GUI не ищет футбольные новости и не требует API-ключа.
Назначение — выбранные оператором футболисты Первой немецкой Бундеслиги;
исторические клубы и национальные сборные внутри их статей обрабатываются отдельно.
Мониторинг лиг и самостоятельное исследование статистики не реализуются.

**В Windows GUI публикация разрешена исключительно на Участник:Zambrowski/testbot.** Основное
пространство запрещено двумя независимыми проверками в Publisher и API-клиенте.
По умолчанию Dry Run. В GUI Automatic отключён. Manual требует входа,
проверенного плана, просмотра diff и подтверждения каждой изменяемой операции.

## Открыть обычным способом

В сборке Windows дважды щёлкните START.bat либо WikipediaStatsUpdater.exe.
Python устанавливать не нужно. Переносите всю папку вместе с _internal.
В исходном проекте START.bat создаёт .venv и ставит зависимости при первом
запуске; для этого нужны установленный Python 3.12+ (команда py) и интернет.
TEST.bat устанавливает тестовые зависимости и запускает pytest локально.

Ручной запуск исходников в PowerShell:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip install -e . --no-deps
.\.venv\Scripts\python.exe run_gui.py
```

Загрузить JSON → проверить статьи → выбрать строку → показать изменения →
подтвердить или отклонить. Ошибочную операцию подтвердить нельзя. Для Manual
сначала выберите режим, затем просмотрите и подтвердите операции: смена режима
очищает старые подтверждения. Общий предпросмотр отчёта содержит все готовые
группы; публикация строится заново только из утверждённых групп.

## Реализовано

- Прежние JSON 1.0, существующая замена матчей/голов и old_value_mismatch сохранены.
- JSON 1.1: update_stats, add_club, add_national_team, add_season, add_competition,
  update_totals, update_current_club, update_career_period и update_date.
- Несколько строк клубов и сборных; транзакционные group_id с полным отказом
  группы при ошибке. Связанный трансфер: закрыть период, добавить новую строку,
  изменить нынешний клуб. Возвращение, аренда и резерв различаются.
- Новые сборные различаются по возрасту и QID; отсутствующее или пустое поле
  национальной карьеры создаётся точечной вставкой.
- Отдельный разрешитель: 22 идентичности немецких клубов, альтернативные имена,
  QID, проверка реальной русской статьи и обратной ссылки Wikidata. Справочник
  содержит исторические клубы и не является списком участников текущего сезона.
- Новые сезоны в поддерживаемом существующем блоке КлСтат, счётчики сезонов,
  программный пересчёт клубных/карьерных итогов. Обновление существующих
  соревнований требует полного итога категории и явного правила сопоставления.
- BotPasswords; пароль, cookies и токены только в памяти, не в файлах/журнале.
- Manual: один POST на выбранный набор групп, повторная проверка ревизии и
  старых данных, baserevid/basetimestamp, CSRF, assertuser, nocreate и maxlag.
  После изменения ревизии нужны новый просмотр и новые подтверждения.
- Автоматическая резервная копия перед записью; ручной предпросмотр и публикация
  восстановления всей тестовой страницы из выбранной копии.
- Русский GUI: отдельные ошибки получения, источников, данных и выполнения;
  статусы операций и статьи, корректный статус решения, фоновые QThread.
- CLI Dry Run, JSON-отчёт, JSONL-журнал, ограничение частоты и тайм-ауты API.

Статистические источники **не проверяются независимо**. Их URL не запрашиваются.
ready означает проверку старых данных, структуры и, для вставок, идентичности
объекта — не доказательство правильности новой статистики.

## Поддерживаемый викитекст и безопасные отказы

Карточка Футболист; спортивная карьера с тройками период/команда/матчи (голы).
Регистр имени шаблона несущественен; н.в., ссылки, флаги, комментарии и сноски
сохраняются. Число меняется по границам AST, без глобальной замены.

КлСтат с 1–4 уникальными явно заданными категориями, Клуб, Лига, Сезон,
ИтогоЗаКлуб и Итого; по два целых числа на категорию, корректные сезоны для
rowspan. Новая строка клонирует оформление существующей строки. При неполных
показателях, неизвестных значениях, неизвестных таблицах или неоднозначностях
выдаётся безопасный отказ. Нельзя считать неизвестное значение нулём.

Не поддерживаются пока: произвольные wikitable/списки матчей сборных;
создание нового блока клуба в статистической таблице; вставка сезона в середину
или с новой лигой; автоматическая новая колонка соревнования; историческая
вставка карьеры в середину; изменение начального года периода; неизвестные
форматы дат/статистики; часть стран/объектов без подтверждаемого флага.
Для новой колонки показывается structure_change_required и предложение,
которое не исполняется автоматически. Такое сложное изменение должно быть
спроектировано отдельно. Публикация в статьи и автономный бот отсутствуют.

Карточка не синхронизирует автоматически биографию, номер, даты и все таблицы:
связанные подтверждённые изменения явно включаются в JSON-группу. Даты карточки
меняет только update_date по as_of, а не текущие часы. Текстовые даты под
таблицами отдельно не переписываются. Перед пользовательской публикацией
проверьте весь diff и наличие необходимых связанных изменений.

Версия 1.0 сохраняет прежнее планирование чисел без автоматического изменения
итогов. Если такая правка таблицы делает арифметику неверной, публикация блокируется;
для полноценной таблицы используйте 1.1.

## Автоматическая проверка и сборка

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean WikipediaStatsUpdater.spec
```

Или TEST.bat / build.ps1 из подготовленного окружения.
Результат сборки: dist/WikipediaStatsUpdater/WikipediaStatsUpdater.exe.
Правило spec исключает конфликтующую ICU DLL из Poppler; системная ICU Windows
используется Qt. Сборка onedir: EXE нельзя переносить отдельно от _internal.

Фактически выполненные проверки и версии — verification-stage23.txt.
Автоматические тесты публикации используют имитацию API; живую авторизацию,
сохранение и восстановление предстоит испытать совместно с пользователем.
Реальных публикаций при разработке не было. Проверка на чистой другой Windows
и подпись цифровым сертификатом не выполнялись.

## Структура

```text
wiki_stats/      прежние parser/mapper/planner/client/gui/cli/audit и новые
                structural_editor, entity_resolver, transactions, backup, publisher
tests/          регрессия этапа 1, новые операции, защита публикации, GUI
tests/fixtures/ настоящие ревизии трёх статей и Участник:Zambrowski/testbot
examples/stage23/ тестовые пакеты, полный стенд, оригинальная резервная копия
scripts/        генератор синтетических примеров без сетевой записи
START.bat       запуск исходников или расположенного рядом EXE
TEST.bat        локальные автоматические испытания
WikipediaStatsUpdater.spec / build.ps1
requirements.txt / requirements-tested.txt / pyproject.toml
```

В GUI запросы идут к Wikipedia/Wikidata для структуры и идентичности. Сервер отдельно использует API-Football.
Частота минимум одна секунда, ограниченные повторы чтения; POST записи не
повторяется автоматически. Журнал: %LOCALAPPDATA%/WikipediaStatsUpdater/audit.jsonl.
Резервные копии: та же папка /backups. Файлы не содержат учётных данных.
Списки разрешённых страниц не расширяются из JSON или пользовательской настройки.
